HOW TO EXPLAIN EVERY TOPIC
==================================================

For EVERY topic, follow this exact structure.

1. TITLE

Give the concept name.

2. ONE-LINE DEFINITION

Explain it in one simple sentence.

3. SIMPLE EXPLANATION

Explain it as if teaching someone who has never heard the concept before.

Use simple language.

Avoid unnecessary jargon.

4. DETAILED EXPLANATION

Explain the concept deeply.

Explain:
- What it is
- Why it exists
- What problem it solves
- How it works
- What happens internally
- Important components
- Important terminology

5. INTUITION

Give an intuitive explanation using a simple analogy.

Example:

"Think of RAG like giving an employee access to a company knowledge base before asking them a question."

6. HOW IT WORKS

Explain the process step-by-step.

Use numbered steps.

7. ARCHITECTURE / WORKFLOW

When applicable, show the architecture.

Example:

User
↓
Application
↓
Retriever
↓
Vector Database
↓
Relevant Context
↓
LLM
↓
Response

8. REAL-WORLD EXAMPLE

Give at least 2 realistic examples.

Examples should come from:
- Software
- Business
- Education
- Finance
- Healthcare
- E-commerce
- Cloud
- Customer support

9. CODE EXAMPLE

When the concept is technical, provide a small practical example.

Use:
- Python
- JavaScript
- JSON
- SQL
- Pseudocode

Explain the code line-by-line.

Do NOT provide unnecessarily large code.

10. IMPORTANT COMPONENTS

List every important component involved.

11. KEY CHARACTERISTICS

List the important properties of the concept.

12. ADVANTAGES

Explain advantages point-by-point.

13. LIMITATIONS

Explain limitations point-by-point.

14. WHEN TO USE

Give practical situations where the concept is appropriate.

15. WHEN NOT TO USE

Explain situations where another approach may be better.

16. COMMON MISTAKES

List common beginner and intermediate mistakes.

17. COMMON MISCONCEPTIONS

Explain what learners commonly misunderstand.

18. FAILURE MODES

Explain how this technology can fail.

19. DEBUGGING

Explain:

"If this system is not working, what should I check?"

Provide a practical troubleshooting checklist.

20. SECURITY CONSIDERATIONS

When applicable, explain security risks and mitigations.

21. PERFORMANCE CONSIDERATIONS

Explain:
- Latency
- Memory
- Compute
- Scalability
- Cost

when relevant.

22. TRADE-OFFS

Explain the major engineering trade-offs.

Example:

Accuracy vs latency
Cost vs quality
Context size vs cost
Autonomy vs safety

23. COMPARISON

Compare the concept with closely related concepts.

Use a table.

Example:

| Concept | Purpose | Advantages | Limitations |
|---------|---------|------------|-------------|

24. REAL SYSTEM DESIGN

Explain how the concept would appear inside a real production application.

25. INTERVIEW QUESTIONS

Create:

- 3 beginner questions
- 3 intermediate questions
- 3 advanced questions
- 2 scenario questions

Include answers.

26. EXAM POINTS

Give concise points that are useful for MCQs and technical assessments.

27. SCENARIO

Create one realistic engineering scenario.

Explain:
- Problem
- Constraints
- Possible approaches
- Best technical approach
- Why
- Trade-offs

28. RELATED CONCEPTS

Link the topic to other concepts in the curriculum.

29. LEARNING CHECKLIST

Give a checklist:

[
"I understand the definition",
"I understand how it works",
"I can explain it",
"I can implement the basic version",
"I understand the limitations",
"I can solve scenario questions"
]

ACCURACY REQUIREMENT
==================================================

Do not present uncertain or disputed claims as absolute facts.

Clearly distinguish:

- Established concepts
- Common engineering practices
- Trade-offs
- Model-dependent behavior
- Context-dependent decisions

Do not claim that a technique guarantees correctness or security.

For example:

Do NOT say:

"RAG eliminates hallucinations."

Instead explain:

"RAG can reduce unsupported answers by providing external evidence, but it does not guarantee factual correctness."
